# Supply Chain Security

## Overview

The EnterpriseAI package implements the following supply chain security controls:

## Pinned Versions

All upstream component versions are pinned in `manifest/dependencies.lock.json`. No floating version references are used in release builds. CI validates that no `PLACEHOLDER` values remain before building a release.

## Hash Verification

SHA256 hashes for all vendored components are verified during CI packaging in `packaging/New-DependencyBundle.ps1`. A hash mismatch causes the build to fail with exit code 5.

## SBOM

A Software Bill of Materials (SBOM) in SPDX 2.3 JSON format is generated during CI packaging and attached to each GitHub release. The SBOM lists all vendored components and their versions.

> Note: The current SBOM is a stub generated by `packaging/Generate-Sbom.ps1`. For production use, replace this with a dedicated SBOM generation tool such as [Microsoft SBOM Tool](https://github.com/microsoft/sbom-tool), [Syft](https://github.com/anchore/syft), or [CycloneDX](https://cyclonedx.org/).

## Offline Installation

Endpoint workstations never download from the Internet during installation. All components are bundled in the release artifact. This eliminates a class of supply chain risks at install time.

## CI Isolation

The release workflow (`release.yml`) uses least-privilege permissions (`contents: write` only for the release creation step). It does not execute untrusted pull request content.

## Monitoring

- Subscribe to security advisories for [Ollama](https://github.com/ollama/ollama/security/advisories), [LiteLLM](https://github.com/BerriAI/litellm/security/advisories), and the Python runtime.
- Review `manifest/dependencies.lock.json` before each release.
- Verify the SBOM attached to each GitHub release.
